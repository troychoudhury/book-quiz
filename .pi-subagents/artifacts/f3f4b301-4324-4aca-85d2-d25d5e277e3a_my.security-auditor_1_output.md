### Tokens in localStorage → **NOT FIXED** ❌ (was High #4)

- **Location**: `frontend/src/stores/authStore.ts:25-39`
- zustand's `persist` middleware (imported from `'zustand/middleware'`) defaults to `localStorage` for its storage backend. The store is configured with `name: 'auth-storage'` and `partialize` serializes both `accessToken` and `refreshToken` into localStorage.
- `frontend/src/services/api.ts:27` — reads `useAuthStore.getState().accessToken` for the auth interceptor.
- `api.ts:63` — reads `useAuthStore.getState().refreshToken` for silent refresh on 401.
- The grep for raw `localStorage` returned no matches, but zustand's `persist` middleware uses it under the hood. This is confirmed by the fact that no `storage` option override (e.g., `storage: createJSONStorage(() => sessionStorage)`) is passed to `persist()`.
- **Impact**: Any XSS vulnerability in the app or its dependencies can extract both tokens and exfiltrate them. The refresh token is long-lived (7 days). No httpOnly cookie approach has been implemented.
- **Severity now**: 🟠 High (unchanged from original)

### Quiz Answer Oracle → **PARTIALLY MITIGATED** ⚠️ (was High #7)

- **Location**: `backend/app/api/quiz.py:171-174`
- The `POST /{attempt_id}/answer` endpoint still returns `is_correct` (boolean) and `correct_choice_id` (string) in the `AnswerResponse`.
- **What was improved**:
  - `correct_choice_id` is now only populated when the answer IS correct (line 174: `str(choice.id) if is_correct else ""`). Previously, it leaked the correct answer on every attempt.
  - Duplicate-answer prevention: `quiz.py:152-160` now raises `400` if the same question is answered twice in the same attempt. This blocks brute-forcing all 4 choices within one attempt.
- **What remains an oracle**:
  - `is_correct` is still returned per-question, giving binary feedback on every answer.
  - An attacker can start unlimited new quiz attempts and systematically try different answers across attempts to deduce correct answers.
  - The `complete` endpoint also returns full results including `correct_choice` and `is_correct` per question, which is the intended design (reveal after completion).
- **Severity now**: 🟡 Medium (was 🟠 High — duplicate prevention reduces brute-force from 4 calls to 1 call per question per attempt, but the oracle still exists across attempts)

- **Location**: `backend/app/api/auth.py:14-26`
- `_validate_password_strength()` now enforces:
