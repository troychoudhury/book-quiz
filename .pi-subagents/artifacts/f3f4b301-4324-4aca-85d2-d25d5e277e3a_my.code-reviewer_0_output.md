## 🔴 Critical Findings

1. **`frontend/src/stores/authStore.ts:35-55` + `services/api.ts` — tokens still in localStorage, contradicts ADR-003 (residual from prior review #4, NOT addressed).** Zustand `persist` writes `accessToken`/`refreshToken` to `localStorage['auth-storage']`; tokens returned in response body. Any XSS = full account takeover. Also still **no refresh-token rotation/revocation** — `auth.py:65-82` issues a fresh refresh token but never invalidates the old one; a stolen refresh token remains valid for 7 days.

## 🟡 Major Findings

2. **`backend/app/api/quiz.py:107,178` — answer/complete still have no ownership check.** `get_current_user` exists but is used only by `profile.py`; any unauthenticated caller can answer or complete any attempt by ID. If rate limiting/auth get wired to quiz routes later, this becomes an authorization hole (prior review residual).
3. **`backend/app/core/security.py:25-30` — limiter `storage_uri="memory://"` hardcoded** despite comment claiming "Redis-backed in production"; `fly.toml:41` runs `--workers 2`, so limits are per-process and trivially bypassed. Limiter is also constructed at import time with `settings.rate_limit_enabled` — toggling the env var at runtime (as my smoke test did) does not re-create it.
4. **`backend/app/schemas/quiz.py:33` — `CompleteQuizRequest.email` still silently ignored** in `complete_quiz` (PROJECTS.md "ask for email to send results" promise unimplemented); frontend `api.ts` sends it.
5. **`fly.toml:42` — `celery -A app.worker` but `backend/app/worker.py` still missing** (celery now in requirements, but the worker boot will fail; prior finding #19 partially addressed).
